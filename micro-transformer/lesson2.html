Why does word order matter?

Lesson 1's model summarized everything before the next word by averaging the word vectors. Averaging can't see order: the average of (wolf, hunts, deer) is exactly the average of (deer, hunts, wolf). This lesson adds yes/no questions, where that matters: wolf hunts deer ? is yes, but deer hunts wolf ? is no. Same words, opposite answers.

The obvious fix is to give each position its own vector and add it to the word before averaging. That doesn't work, and the averaging model below already has it: the position vectors add up to the same total whichever word sits where, so swapping two words still gives the same average. What works is to stop averaging and concatenate: lay the word vectors end to end in fixed slots, so the model can see which word came first.

Slots: order survives
[ wolf | hunts | deer | ? | pad ]
[ deer | hunts | wolf | ? | pad ]
16 + 16 + 16 + 16 + 16 = one 80-number vector
Slotting means concatenating: the five 16-number word vectors are laid end to end into one long vector, so its size is the sum of the pieces' sizes. Empty slots hold <PAD>. The next layer has a separate block of weights for each slot, so wolf in slot 0 and wolf in slot 2 get multiplied by different weights. No position vectors needed: the slot is the position.

The math, with a tiny example ▾ Use 2-number vectors: wolf = (1, 0), deer = (0, 1), and for the averaging model, position vectors P0 = (0.5, 0) and P1 = (0, 0.5).

Averaging. "wolf deer" gives wolf+P0 = (1.5, 0) and deer+P1 = (0, 1.5), averaging to (0.75, 0.75). "deer wolf" gives deer+P0 = (0.5, 1) and wolf+P1 = (1, 0.5), also averaging to (0.75, 0.75). In general, the average splits into ¼(sum of word vectors) + ¼(P0+P1+P2+P3), and the position part is the same for every 4-word question, so it can't carry order.

Concatenating. "wolf deer" becomes [1, 0, 0, 1] and "deer wolf" becomes [0, 1, 1, 0]: two 2-number vectors make one 4-number vector, and the two orders give different vectors.

Why that matters. The output layer multiplies by a weight matrix W. Split W into one block per slot and the result is W0·x0 + W1·x1 + W2·x2 + …, a different matrix for each slot. Averaging instead computes ¼W·x0 + ¼W·x1 + …, the same matrix for every word, so swapping words can't change the answer.

Predict first: which model can get both answers right, and does more training help the other one?
Only the slot model. The averaging model turns both questions into the exact same vector, so it must give them the same answer. For the hunts pairs it can get one right at most, and no amount of training changes that. Train 50 steps and check: the slot model usually gets both right after 30 to 45 steps.

If slots work, why do we need Lesson 3? ▾ Slots are rigid. Every slot has its own fixed block of weights, so the model needs a maximum sentence length decided in advance (5 words here), and each slot only learns what usually sits there: slot 0 has only ever seen a subject, slot 1 a verb. Real transformers still add position vectors to word vectors, but instead of averaging or fixed slots they use attention, which decides how much each earlier word matters based on what the words are. That's Lesson 3.
